The shape of it

Four layers. Each answers one question.

Keep them separate and none of them rots. Collapse them and you get a folder of prompts nobody trusts.

SKILLS

How is the work done? Borrowed from their sources, never forked into your repo.

GUARDRAILS

What may an agent never do? Enforced before the tool call, not after the commit.

GATES

What must be true to commit? One script per gate. Same script in the hook and in CI.

AUTOMATIONS

When, and as whom, does an agent run? Ticket to PR to merge, no dispatcher.

Design decisions

Three things that make it hold.

Skills are borrowed, never vendored.

Scaffold ships a list, not files. Fork someone's skill into your repo and you own a stale copy — a content hash tells you that upstream changed, never what it broke. So the factory points at sources and installs fresh.

Automations ship as patterns, not instances.

Every ticket key, label string and host path inside an automation belongs to the repo that wrote it. A copied one still pointing at another project's epic will happily file your tickets there. So you derive yours from the conventions instead of inheriting someone's.

Guardrails fail closed.

Agent hooks fail open on more than one harness — malformed JSON silently allows the command. So the deny path is exit 2, the commit gate never goes away, and setup reports a coverage table instead of claiming success. A silent success is indistinguishable from a fail-open.
